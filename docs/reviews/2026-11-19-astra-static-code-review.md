# Independent ACE static code review — source semantics, failure paths and reinvention

**Review target:** `main` at `bd170d197dcafc5cd30d0b8d6220ba6eca4fde5b` (the prompt-only advance from `5f6d941`). Findings refer to this tree unless a PR SHA is called out. **Method:** read-only source review; trace callers, state owners, failure paths and the model-visible result. No product code or tests were run for this review. Earlier local diagnostics in the other audit appendices are supplemental observations, not proof for findings below.

**Branch boundary:** at the initial source review, PR #288 was still an unmerged Bifröst physical-send candidate at `8358c268b4c07fef2caae9d7dc1c74d34ad3ab5b`; PR #291 was a separate unmerged repair candidate (head later advanced to `c293de9da7e744ddb4c45a5fae76fe5ec9a86c30`). Neither set of fixes is credited to the audited `main`. Check live PR state before treating either as current.

**Implementation supplement (20 November):** [ACE remediation engineering decisions](2026-11-20-ace-remediation-engineering-decisions.md) translates these findings into concrete native mechanisms, alternatives, deletion/migration boundaries and adversarial acceptance tests. It is a **proposal**, not another independent reproduction or an accepted ADR. In particular, Qdrant's atomic alias update is **not** a monotonic generation CAS; an archive-only proof must survive the `created:true` → crash → `created:false` window; and a successful empty non-Git search requires verified freshness.

## A. Executive verdict

**SIGNIFICANT COURSE CORRECTION NEEDED — retain ACE's source-verification core, but simplify and repair publication, freshness, retention and delivery contracts before broadening providers.** The basic idea remains sound: a workspace-bound retrieval engine should give concise, cited context while retaining exact source bytes. TypeScript + Effect, Qdrant's official client/native query fusion, parsed spans, exact working-tree reads, and Bifröst as the single delivery owner are defensible choices.

The current code is not just “a lot of infrastructure.” Several boundaries disagree about what their own results mean:

1. Qdrant's stable collection is mutated with a per-process queue, then old path versions are deleted without a generation condition. Two ACE runtimes sharing one workspace can let a stale publisher erase the live publisher's changed-path points.
2. Non-Git freshness observation detects only size and modification-time changes. Same-size edits with restored timestamps are invisible to the observer; unchanged Qdrant search results can then omit newly relevant code while reporting required code coverage satisfied.
3. The memory archive writes final content and metadata files in place. A crash can strand a partial blob/JSON file; retry treats the existing content-addressed blob as success without verifying it. A second crash window can lose the “never projected” proof needed for safe archive-only deletion.
4. The gateway calls a transform configured for `required: ['code']`, but the retrieval provider can still append optional RepoMap evidence. That evidence is explicitly marked `freshness: 'unknown'`; required-source coverage later overwrites the bundle's partial state, and the final projection ignores the warning. The model can receive a graph map as prepared context without its uncertainty.
5. Every selected source file is copied to a new UUID artifact on every retrieval. The artifact port has no delete, expiry, deduplication or workspace scope; the default store accumulates complete private source files indefinitely, including when the gateway never exposes an expansion route.

These are code-path findings, not benchmark-based claims. I do **not** conclude that current production users have lost data, that two replicas are deployed, or that ACE reduces/increases task success. The architecture decision to keep physical provider dispatch fail-closed on `main` is correct; a safe stop is not a completed product loop.

## AS-IS, target and minimum useful ACE

**AS-IS on audited main:** `src/bin/ace-gateway-http.ts` composes `src/bin/ace-runtime.ts`; runtime registers and snapshots the workspace, builds AST candidates, embeds/upserts them in Qdrant, creates the Qdrant context provider, and starts the local authenticated TypeScript projection server. Bifröst's Go connector posts a native Responses request to that service. ACE can return a prepared body, but the main connector stops before provider generation. Indexing can additionally compose RepoMap, LSP, reranker and optional Vertex; current projection explicitly requests code only. `ace-memory` is a separate archive/import/reconcile CLI whose Graphiti projection adapter is unavailable. Harbor and the old context-command implementation are separate from the active gateway path.

**TARGET:** keep one agent-facing path and one retrieval owner. Treat exact workspace bytes and source identity as authoritative; every optional source must be omitted or visibly uncertain, never silently promoted to verified evidence. Make Qdrant publication atomic at the workspace version boundary. Preserve immutable history while making writes, retries, deletion and retention recovery-safe. Provider identities and benchmark labels must name observed implementations, not defaults. Keep unproven providers off the minimum path.

**MINIMAL VIABLE ACE:** one runtime writer per workspace (or immutable versioned Qdrant collections switched through the existing alias boundary), exact local source and one maintained structural extractor, genuine local embeddings, concise directly verified snippets, and one reviewed native Responses physical-send route. No graph memory, remote docs, optional model tool surface, second AST provider, or reranker until paired tasks show they help. The agent's native file tools can remain the lossless expansion path if the configured agent actually has them; do not claim that `ace_expand` is available through the current Gateway.

## C. Highest-impact findings

### F1 · P1 · CONFIRMED (conditional deployment topology) — stable Qdrant publication is not cross-process safe

**Call path:** `ace-runtime.ts:1051–1079` builds a changed-path generation and calls `publishBuild`; that path calls `mutateQdrantChangedPaths` in `qdrant-context-provider.ts:850–872`. Within that function, new points are upserted and verified (`:365–407`), then `deletePaths` removes all points for the workspace/path except the publishing `indexKey` (`:408–418`). `http-provider-boundaries.ts:314–331` implements that delete as a Qdrant filter on `workspace_id` + `repo_path` and an optional `must_not index_key`; it has no generation predicate. The serialization in `makeWorkspaceSync` (`workspace-sync.ts:175–183`) is a JavaScript closure, not a cross-process fence. `QdrantCodeCandidatePort.deleteWorkspaceVersions` already has a `beforeGeneration` fence (`ports.ts:127–138`, adapter `http-provider-boundaries.ts:349–369`), but changed-path deletion does not use it.

**Counterexample:** runtime A indexes path `src/x.ts` at content v1/key K1. Runtime B observes v2, publishes K2, verifies it, deletes older points and advances its own sync state. A slower A then publishes its stale v1/K1 and deletes every point for that path except K1, including B's v2/K2 points. B's filesystem manifest still says v2 and its next request sees no workspace change, so it does not reconstruct the now-missing Qdrant candidates. Exact reads prevent quoting stale v1 as current, but cannot retrieve the deleted v2 candidates; recall can silently disappear.

This is reachable whenever two runtime processes share workspace ID + collection and overlapping updates; the runtime has no singleton lock or rejection. **Remedy:** prefer the accepted immutable-collection + atomic Qdrant alias publication design, using the existing `qdrantCurrentAlias`/`switchQdrantAlias` boundary after complete snapshot verification; alternatively enforce one process per workspace with an OS/database lock that covers build publication and deletion. A local JS queue or a larger timeout is not enough. Avoid creating a custom distributed lease service before evaluating Qdrant's native publication boundary.

**Retire/avoid:** direct shared-collection delete-after-upsert as a publication protocol unless it gains provider-native CAS/generation conditions. **Acceptance to add later:** deterministic two-process barrier test: pause A after v1 snapshot, let B publish v2, resume A; v2 membership must remain visible and retrievable. Also test same-generation races and process restart. This is static review; not reproduced here.

### F2 · P1 · CONFIRMED — non-Git source freshness can silently miss a same-size edit

`node-workspace-port.ts:108–129` gathers only `sizeBytes` and `mtimeMs` for non-Git roots. `observeNonGitChanges` compares only those fields (`:206–230`); it does not compare ctime, file digest, a watcher sequence or a content identity. `workspace-sync.ts:100–108,126–151` exact-reads only paths returned as changed/added or explicitly forced. If a source file is edited to different bytes of the same size and its mtime is restored, the non-Git observer reports no change and never hashes/reads it. The initial full snapshot does hash exact bytes (`node-workspace-port.ts:71–105,407–431`), but that does not solve later invalidation.

If the changed file is not among old Qdrant hits for the new query, request-time verification never reads it; the old index can return no candidate and code coverage can remain satisfied. Main's G2 currently blocks a truly empty Gateway projection, but the retrieval port can still represent this as a successful complete empty result; the open PR #291 adds an empty-success path and would make correct invalidation even more important. Git-backed workspaces use Git diffs; this finding is specifically the supported non-Git path.

**Remedy:** either mark non-Git manifests as freshness-unknown until an exact rescan, or maintain a reliable watcher/journal that cannot lose same-metadata changes, with exact digest verification before promoting a snapshot. If periodic content hashing is chosen, measure its cost on large workspaces; do not call size/mtime alone authoritative. **Acceptance:** non-Git edit with same length and restored mtime must invalidate the manifest before an empty result can be `complete`; watcher overflow/drop must degrade to exact rescan or explicit partial.

### F3 · P1 · CONFIRMED — archive import is not recoverable after a crash during final-file writes

`file-memory-archive.ts:96–123` holds its lock and validates digest, but writes the content-addressed blob directly to its final `${digest}.bin` path with `flag:'wx'` (`:117–119`) and then writes final episode metadata directly with `flag:'wx'` (`:120–122`). It does not write/fsync a temporary file and atomically rename either item. If a process/power loss leaves a partial blob, retry treats `EEXIST` as success without reading/verifying that blob, then commits metadata. `readEpisode` (`:133–145`) later detects the digest mismatch, so the “immutable source truth” becomes unreadable. If metadata is left as partial JSON, retry parses the existing file and returns `PERSISTENCE_FAILED`; the importer has no repair/quarantine path.

**Remedy:** temp-write → flush where the durability contract requires it → verify size/digest → atomic rename for blob; atomically publish metadata last. On `EEXIST`, verify the existing blob against the expected digest rather than assuming success. Give malformed orphan/temp states an idempotent, fail-closed recovery path. Keep digest-based shared-blob protection. **Acceptance:** deterministic failpoints after blob creation/write and during metadata publication; restart and re-import must recover the exact bytes or return a typed unavailable state without committing a successful episode. No filesystem crash test was run here.

### F4 · P1 · CONFIRMED — archive-only “never projected” proof has a permanent crash window

`memory-import.ts:88–96` writes archive-only proof only when `created === true`; the proof is stored later via `outbox.markArchiveOnly`. A crash after `archive.importEpisode` commits but before `markArchiveOnly`, followed by an idempotent re-import, returns `created:false` and permanently skips the proof. `file-projection-outbox.ts:193–223` does not reconstruct it, correctly refusing to infer “never projected” from an absent receipt. `ace-memory.ts:85–110` then cannot use the safe archive-only delete path and tries the unavailable Graphiti provider. A crash while the proof marker itself is being written can also leave malformed proof that `readArchiveOnly` treats as a persistence error.

The fail-closed behavior avoids deleting potentially projected data, but the current write protocol makes a never-projected episode undeletable after a realistic crash. **Remedy:** commit the archive-only/admission state atomically with original metadata, or introduce a recoverable transaction record whose state distinguishes “archive committed, projection never started” from “unknown/possibly projected.” Do not mark legacy records archive-only based only on no current receipt. **Acceptance:** failpoints between original commit, intent/proof commit and acknowledgement; repeat import/reconcile/delete must converge, while pre-existing ambiguous records remain undeletable until verified.

### F5 · P1 · CONFIRMED on the enabled RepoMap path — caller asks for code only, but unverified optional map text can still enter a “ready” projection

The Gateway transformer requires exactly code (`context-transform-service.ts:77–84,140–149`). Yet `qdrant-context-provider.ts:1131–1148` renders and applies RepoMap whenever a RepoMap is configured and `includeCode` is true; it does not check whether `requirements.structural` was requested/allowed. The map evidence is explicitly `proofClass:'derived', freshness:'unknown'` because its aggregate paths are not exact-reread (`:1527–1551`). The adapter then records structural coverage as unavailable/partial (`:1612–1632`), but at `:1646–1654` replaces `mergeEvidence`'s partial/freshness result with only *required* source coverage. Gateway's explicit plan has structural not requested, so the result can have `status:'ready'` in `context-transform-service.ts:189–215` while still containing that unverified map. `responses-projection-service.ts:101–118` checks status, text and selected IDs; it drops `limitations` and forwards only `contextText`. The model does not see the unknown-freshness warning.

This is conditional on a RepoMap provider that returns nonempty content (the default CLI composition may mark RepoMap not-ready; another configured structural provider can enable it). The source comment says to fail closed, but the final required-source overwrite means that claim is not enforced. **Remedy:** do not run/deliver structural/map evidence when the caller did not request/authorize it. If requested optional, omit unverified map text or carry per-path digest/range provenance and revalidate it; if required, preserve typed partial/not-ready through the Gateway. Never rely on a warning that the final adapter discards. **Acceptance:** code-only plan plus active stale/unbound RepoMap must not add map bytes; required-structural plan must remain partial until every delivered path has verified identity.

### F6 · P1 · CONFIRMED unbounded local retention — every retrieval persists another complete source copy

For each distinct selected code path, `qdrant-context-provider.ts:1263–1295` exact-reads the entire source and calls `artifacts.storeExact` before building evidence. `file-artifact-store.ts:22–38` writes a new random UUID `.bin` per call. `ArtifactStore` exposes only `storeExact` and `readRange` (`application/ports.ts:324–331`); there is no delete, expiry, reference count, workspace binding or GC. Runtime defaults this directory to `~/.local/state/ace/artifacts` (`ace-runtime.ts:229–230,306`). Thus repeated requests persist repeated whole-file copies indefinitely, even if no one expands them. These are private source bytes, not just lightweight evidence pointers.

**Impact:** storage grows approximately with selected full-file bytes × retrieval count; old code remains on disk after worktree updates and can outlive the workspace/session. Exact expansion is valuable, but this retention policy is accidental and unbounded. **Remedy:** first clarify whether the active Gateway needs expansion artifacts at all. If not, stop writing them there. If needed, store content-addressed bytes once per digest, bind handles to workspace and lifetime, and add a bounded/verified GC or explicit retention API. Do not silently delete shared originals or impose a source truncation cap. **Acceptance:** repeated identical queries do not multiply stored bytes; expiry/restart preserves active handles and removes only unreferenced blobs; cross-workspace handles fail closed.

## D. Additional confirmed and strongly supported findings

### F7 · P2 · STRONGLY SUPPORTED — working-context “boost” can rank a focused file lower

`qdrant-context-provider.ts:136–171` computes a positive `boost` and multiplies `candidate.score * (1 + boost)`. The production collection is configured with cosine distance (collection setup in `:451–480`); cosine scores can be negative. If all available dense candidates have negative scores, multiplying a focused/dirty candidate by a factor greater than 1 makes its score *more negative*, so descending sort demotes it. This contradicts the intended working-context prior. In addition, Qdrant is already asked for only `retrievalLimit` candidates (`:1097–1111`) before this boost (`:1124–1149`), so a focused/open file omitted by the provider shortlist cannot be rescued by the prior at all.

**Remedy:** establish score semantics/range per configured strategy and use a monotone, calibrated prior or provider-native grouping/ordering; do not multiply negative cosine values. Oversample only with measured cost/recall. **Acceptance:** positive, zero and negative score tables preserve “higher prior never lowers rank”; a focused relevant path outside the initial shortlist is either retrieved by a justified provider-native strategy or reported as not guaranteed.

### F8 · P2 · CONFIRMED — the “delivered” retrieval benchmark stage is recorded before source verification

`qdrant-context-provider.ts:1237–1245` records stage `delivered` from `rankedResults`. Only afterward does the code exact-read candidates and discard stale/mismatched spans (`:1263–1312`), then perform a final source reread and mark changed evidence uncertain (`:1557–1587`). The benchmark collector and quality evaluator treat the `delivered` list as a ranked evidence stage (`retrieval-benchmark.ts:10–20,81–90`; `retrieval-quality-evaluation.ts:42–70`). A stale Qdrant candidate can therefore appear in “delivered” rank metrics even when it never becomes source-verified evidence; a final race can also invalidate it after the stage event.

**Remedy:** name the current stage `shortlisted`/`preverified`, and record `delivered` only from the evidence that survives exact span/digest verification and the final race check. Preserve a separate trace for rejected candidates. **Acceptance:** stale span and final-read-race fixtures appear in shortlist diagnostics but never in delivered recall.

### F9 · P2 · CONFIRMED semantic-scale limit — ACE’s general SHA-256 helper is handwritten and fails beyond a standard message-length boundary

`src/domain/retrieval-benchmark.ts:136–185` reimplements SHA-256. It stores only the low 32 bits of the bit length (`:138–144`), whereas SHA-256 encodes a 64-bit length. For inputs at/above 2^29 bytes (512 MiB), the digest is not the standard SHA-256 digest; the padded-length arithmetic also uses JS 32-bit shifts. That is particularly undesirable in a project that handles generated/large source artifacts and calls values `sha256`. This is not evidence that typical short candidate IDs are wrong. It is an unnecessary cryptographic implementation when adapter boundaries already use `node:crypto` (`file-artifact-store.ts:1,20`; `node-workspace-port.ts:1,90`).

**Remedy:** retire the custom implementation behind a clearly owned digest boundary or use a maintained implementation with the intended runtime portability; use the same canonical vectors for all consumers. In `context-delivery.ts:98–127`, `stableReceiptDigest` separately runs four seeded FNV-1a hashes for a 256-bit-looking bundle ID even though the module already imports `sha256` for receipt IDs. Reuse one digest definition; do not imply that four FNV outputs are cryptographic. **Acceptance:** standard SHA-256 vectors at empty, block-boundary and large-message lengths; bundle IDs use the same documented digest semantics. No large-hash test was run here.

### F10 · P2 · CONFIRMED provenance bug — Gateway result reports defaults rather than the selected provider identities

The runtime resolves actual LSP servers and identities in `ace-runtime.ts:717–755` and actual embedding identities around `:565–600`. The object passed into the context transform instead uses env strings and hardcoded defaults (`:1110–1115`), including `semantic: typescript-language-server/6.0.2`. With Rust/Go/Python auto-discovery or a custom command, the Gateway transform result can label facts as TypeScript LS. The benchmark trace has richer provider identity separately, but the model-bound transform's `providerIdentities` field is false/incomplete provenance.

**Remedy:** pass through resolved identities from the exact active provider instances; omit an identity when it was not measured, rather than substituting a plausible default. Keep “configured,” “resolved,” and “health-probed” distinct. **Acceptance:** each language/server configuration produces the same identity in runtime trace and transform receipt; custom/unavailable providers never inherit the TypeScript default.

### F11 · P2 · CONFIRMED scope/deletion drift — retired model-invoked command code and `ace_expand` instructions remain

ADR-020:15,26 says the prior compatibility/tool routes are removed and no model-invoked context interface remains. Yet `src/application/context-commands.ts:62,112–120,234–282` still defines context-query/expand/status/memory command handlers; `src/domain/context-delivery.ts:382–406` still instructs a caller to invoke `ace_expand`. A repository-wide source search finds definitions and historical references, but no active runtime import/transport consumer; `src/index.ts` does not export these handlers. This is **not** proof that an alternate agent route is running. It is dead, testable surface that contradicts the accepted sole-delivery architecture and creates a misleading expansion promise.

**Remedy:** remove the orphan handler and its exclusively owned tests/code, or quarantine it explicitly as historical/test-only. Do not resurrect it as a gateway fallback. Reconcile the obsolete `ace_expand` clauses in ADR-006/ADR-014 through a history-preserving architecture addendum; ADR-020 is the governing current decision. If expansion is needed, define it through an approved non-model-invoked Gateway mechanism or rely explicitly on the host's own file tools.

### F12 · P2 · CONFIRMED measurement limitation (currently fail-closed) — Harbor evidence artifacts are hashed, not reconciled

`scripts/harbor-four-arm-gate.ts:64–72` checks that each raw-trace, usage-event and failed-run file is nonempty and records its SHA. The gate parses Harbor `result.json` through `readHarborFourArmTrialObservations` (`:76–100` and `harbor-four-arm-trial-evidence.ts:79–124`); that adapter derives tokens from `agent_result`, but sets `successfulAceCalls: 0` and returns no independently correlated successful request/receipt IDs (`:107–124`). The report's `qualityNonInferior` and `costTelemetryComplete` are declared booleans (`harbor-four-arm.ts:244–295`); the usage-event/failed-run file contents are not reconciled against task/arm/request identities. The zero-successful-egress condition currently prevents this adapter from making `rawTrialEvidenceVerified` true, so this is **not** a finding that a 5× release has passed. It is a gate-integrity gap to fix before any future adapter starts populating successful provider egress.

**Remedy:** parse typed usage and failure events; bind every event to the exact frozen task bytes, arm, trial, model/provider/runtime, and request/attempt correlation; derive quality/cost completeness from those records rather than caller booleans. Continue to block while final provider egress is unverified. Keep provider usage distinct from cached-input subsets and task outcome.

### F13 · P2 · STRONGLY SUPPORTED — RepoMap is applied after a shortlist too small for graph recall

Runtime fetches at most the candidate/reranker limit from Qdrant (`qdrant-context-provider.ts:1097–1111`) and only reorders those hits using RepoMap (`:1131–1149`). It cannot add a graph-ranked symbol that Qdrant omitted. The graph text itself can add paths, but is an aggregate derived map without path-bound fresh evidence (F5), so it is not a safe substitute for source-cited candidate recall. This limits the promised Aider-style graph behavior and can collapse multi-file tasks to one file. Prefer Qdrant/provider-native grouping or a measured overfetch + dedupe; do not build a second graph search engine.

## G. What is sound and should survive simplification

- `readStableWorkspaceFile` uses a no-follow descriptor and checks inode/device/size/mtime/ctime around reads (`node-workspace-port.ts:50–69`); strict UTF-8 decoding rejects corrupt bytes rather than inventing replacement text (`domain/source-text.ts:9–31`).
- Code candidate IDs bind workspace/path/source digest/span; selected code snippets are checked against exact current bytes and exact UTF-8 ranges before evidence construction (`local-code-index.ts:98–104`; `qdrant-context-provider.ts:1263–1312`). This is unique and worth preserving.
- The Qdrant adapter delegates query fusion to Qdrant and uses the official SDK. Do not replace it with custom RRF or an ACE network client.
- Bifröst is the only approved agent-facing route; main's deliberate dispatch stop is safer than an unverified fallback. `PREPARED` is not mislabeled provider delivery.
- Immutable originals versus derived memory claims is the correct separation. Keep tombstones/shared-blob checks and fail closed on unknown projection state; repair atomicity rather than weakening deletion proof.
- Provider identity and `not_ready` states are explicitly represented in runtime. Use real identities consistently rather than relaxing those boundaries.
- The current Harbor extractor correctly leaves `successfulAceCalls=0` because a Gateway projection response alone does not prove final model egress. Keep that refusal until receipts are actually bound to provider attempts.

## H. Shortest remediation sequence (no mass rewrite)

1. **Close false-context paths:** gate RepoMap/optional evidence on the caller's source plan; do not let unverified map bytes reach a ready projection. Remove or quarantine the obsolete model-tool façade and its `ace_expand` instructions.
2. **Choose one Qdrant publication owner:** activate versioned immutable collections + Qdrant's atomic alias update, or strictly enforce a singleton runtime per workspace. Delete the competing shared-collection stale-writer path. Acceptance is the two-process barrier scenario in F1.
3. **Make archive writes actually recoverable:** atomic blob/metadata publication; durable, recoverable archive-only proof; preserve ambiguous legacy state. Test failpoints after each durable write before claiming crash safety.
4. **Set artifact retention intentionally:** eliminate per-query duplicate whole-file persistence or introduce content addressing, explicit scope, retention and safe garbage collection.
5. **Define non-Git freshness honestly:** watcher/journal+exact verification or explicit digest refresh. Until then, same-metadata changes must not produce a complete source result.
6. **Correct retrieval/evidence measurements:** monotone working-context prior, shortlist vs verified-delivered stage separation, resolved provider identities. Preserve raw stale/rejected candidates as diagnostics, not delivered evidence.
7. **Repair economics acceptance:** total input+output tokens per accepted task, independent quality outcomes, usage-event semantic binding and final wire receipts. Main's current input-only 5× predicate is not the product metric.
8. **Only after those gates**, run one paired unmodified-Hermes vs Hermes-through-Bifröst task suite with same model/reasoning/tool permissions. Then ablate RepoMap, LSP, lexical, memory and docs separately. Do not require them for the first decision.

## J. Implementation decision clarifications (20 November 2026)

These are **engineering recommendations after the static review**, not newly reproduced findings. The full comparison and test oracles are in the [remediation supplement](2026-11-20-ace-remediation-engineering-decisions.md).

- **F1 — aliases vs writer fencing.** An atomic Qdrant alias swap protects readers from a half-applied alias change but does not prevent a delayed older process from later repointing the alias to an older collection. Prefer a **single authoritative workspace writer** where deployment permits; otherwise independently serialize/fence snapshot promotion with a monotonic generation owner. Do **not** promote alias switching alone as a complete stale-writer fix. Confirm collection cardinality and GC costs in multi-workspace deployments.
- **F2 + G2 — verified empty is a meaningful security boundary.** A non-Git workspace observed only by size/mtime must not be reported as provably complete when a same-metadata content change can be missed. #291's `VERIFIED_NO_CONTEXT_NEEDED` path is safe only if the source snapshot's completeness is actually established; unknown/partial observation must remain blocked or trigger digest reconciliation.
- **F3/F4 — one rename is not a multi-object transaction.** Verify existing immutable blobs on `EEXIST`, stage and flush bytes according to target filesystem durability, and recover partial metadata/intent writes. Positive never-projected proof must be durably recoverable after interrupted import and idempotent re-import; a missing graph receipt proves nothing. Compare a minimal file journal against **SQLite metadata/outbox transactions** before building an increasingly complex custom transaction engine. SQLite does not atomically commit external blob files or graph calls.
- **F5/F13 — trust the request's source plan.** Gate optional RepoMap at **both computation and delivery**; `includeCode` must not silently authorize unverified structural output. Revalidating selected code snippets does not make an aggregate derived map current. Prefer measured source diversity/overfetch through Qdrant over a second home-grown graph index.
- **F6/F11 — delete before rebuilding.** The active Native Responses path cannot invoke the historical `ace_expand` interface. Inspect exact handle consumers and stop persisting whole-file retrieval artifacts on paths that need no expansion. Only build content-addressed, scoped, expiring artifact storage if an active consumer remains.
- **F8/F10/F12 — evidence is a contract.** `delivered` must mean final source-verified text actually selected for model delivery; provider identities must describe resolved instances; usage artifacts must reconcile by task/request/attempt/model, not merely exist and have hashes. #291's B1 total-token arithmetic fixes only the verdict predicate, not full provider-evidence attribution.

**Decision discipline:** use a narrow T0/T1 fix when the trust boundary and implementation choice are already determined; seek G02 only for material publication, persistence or provider-authority redesign. Preserve historical negative evidence and the original audit SHA; do not claim the proposed improvements were run or merged.
