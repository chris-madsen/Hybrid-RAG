# Appendix — What the gateway actually delivers (19 November 2026)

**Verdict: local preparation works on fixtures; agent delivery is deliberately disabled.** At ACE `bd170d197dcafc5cd30d0b8d6220ba6eca4fde5b`, configuring a provider and opting in does not let Hermes complete even one model turn through this connector. This is a release blocker, not evidence of a privacy breach. Keep the denial until the last physical write is controlled. A separate question remains even after dispatch works: does the added context avoid enough later turns to pay for itself?

## Trace at the audited revision

1. `integrations/bifrost/ace-connector/plugin/main.go:34–61,84–155,178–235`: initialization requires source provenance, local projector credentials and a single workspace. The HTTP hook admits `/v1/responses` for preparation, extracts visible query text, requires session correlation and an explicit provider/model, then mints an ingress ID (also the attempt-group ID). Neither that ID nor the body digest attests a physical write or the durable Hermes transcript. Other generation paths are rejected, not translated.
2. `integrations/bifrost/ace-connector/responses.go:141–215`: the client sends a bounded, authenticated, deadline-bound POST to the exact loopback v2 project path. Redirects are refused. The envelope carries the raw request encoded as Base64, its digest, and the query again. This HTTP exchange is with ACE, **not the model**.
3. `src/bin/ace-gateway-http.ts:1–3` selects the runtime; `src/bin/ace-runtime.ts:1090–1139` constructs the allowlist, explicit cloud opt-in, file audit sink, transform and assembler (or typed unavailable transform). `src/transport/gateway-projection-http.ts:84–97,125–157` authenticates and invokes the Effect service. `src/domain/responses-projection.ts:25–59,65–97` checks size, binding, model, explicit `store:false` and absence of opaque continuation handles. This checks the request, not provider retention.
4. `src/application/responses-projection-service.ts:58–118` checks transcript claims, original input and policy before retrieval, verifies result identity/readiness and scans selected text. `src/domain/responses-projection.ts:127–179` collects visible text for deduplication and prepends one developer item while preserving the original native items. Go validates both digests and protected content (`responses.go:60–139,225–238`); the hook replaces the ingress body (`plugin/main.go:236–245`). The next normalized model hook returns a 409 short circuit with fallback disabled (`plugin/main.go:294–319`). Neither PREPARED nor HTTP 200 means delivered. Capabilities advertise no routes and delivery recording returns 501 (`gateway-projection-http.ts:60–83`).

## Prioritized findings

**G1 · P1 · CONFIRMED — No dispatch path for a configured agent.** Even a stateless, policy-allowed request with fresh evidence stops at the unconditional hook above. `PreRequestHook` is a no-op; `PostLLMHook` passes through. There is no demonstrated stream, retry, fallback, acknowledgement or task completion here. The `projection-retry` tests import `src/domain/memory.js` (`test/projection-retry.contracts.test.ts:1–10`); they do not exercise provider retries. **Next gate:** retain quarantine, exercise one pinned native route against a loopback receiver with synthetic data. Compare final method, destination, route, body and `store:false`; count actual writes for success, denial, cancellation, and a transient failure. Only then consider enabling that route. For streaming, separately test ordered tool/text deltas, terminal success/error/incomplete, disconnect before/after first delta, and no transparent replay after partial output. Let Bifröst own streaming and retries; ACE checks each write, not each user prompt. Do not promise exactly-once provider execution after an ambiguous disconnect.

**G2 · P1 · CONFIRMED — Nonempty code evidence is mandatory even when it adds no value.** `src/application/responses-projection-service.ts:81–103,110–118` always requests code and rejects empty text, no evidence IDs or non-ready results; `src/bin/ace-runtime.ts:1123–1139` intentionally supplies an unavailable transform during outages. A final summary turn with no relevant code cannot simply proceed on an authorized, successful empty search. This is distinct from a missing index, policy denial or audit failure. Policy is automatic: the startup opt-in and provider allowlist plus local audit (`ace-runtime.ts:1090–1101,1131–1136`; service `:24–53`) do not ask a human per turn. It is retrieval availability, not interactive approval, that couples every turn to the index. **Fix/test:** agree a narrow contract change for a verified ‘no evidence needed’ decision inside the same gateway. Test no-code summary, genuine empty result, stale required code, outage and policy denial separately. Only the first two are candidates for unchanged input, and only under G1's final-write policy. Never convert an unknown into an empty success.

**G3 · P1 · CONFIRMED mechanism; net economics UNKNOWN — Projection adds evidence; it does not shorten the supplied history.** `src/application/responses-projection-service.ts:87–93,101–118`; `src/domain/responses-projection.ts:127–155,162–179`. A long tool transcript is retained even when matching code can be represented by a short reference in the *new* evidence. A near-limit body can become too large after augmentation; the 4 MiB transport guard is not a model token budget. Do not remove opaque reasoning or tool pairs to make a size target. **Experiment after G1:** replay matched tasks in baseline Hermes and gateway Hermes with identical model, reasoning, workspace, evaluator and stop conditions. Include failed tasks and retries; report accepted tasks, input/output/cached usage, actual cost per accepted task, retrieval/embedding cost, cold start and p50/p95 turn latency. Count physical attempts and flag missing usage rather than treating it as zero. Prefer omitting unhelpful additions before introducing history rewriting. No evidence here establishes a fivefold saving or a fivefold loss.

**G4 · P2 · CONFIRMED — Go and TS disagree on empty continuation text.** `plugin/main.go:247–290` skips a blank tool output and falls back to earlier visible user text. `src/domain/responses-projection.ts:100–120` immediately returns the empty string; `src/application/responses-projection-service.ts:77–79` blocks the mismatched query. A successful tool with no stdout after a user question is enough; this is an ordinary agent turn. Worse, TS returns a typed BLOCK but `responses.go:121–123,235–238` converts it into a client error and `plugin/main.go:236–241` reports 503 ‘not ready’. A caller may retry a deterministic denial as an outage. **Fix/test:** use one documented last-nonblank rule and a shared fixture table for Go and TS (empty, whitespace, mixed image/text, output-only); preserve the sanitized denial code end to end and distinguish retryable unavailability. No protocol translator needed.

**G5 · P2 · STRONGLY_SUPPORTED — Caller cancellation bounds waiting, not necessarily retrieval work.** Go supplies a live context and deadline (`plugin/main.go:223–235`; `responses.go:193–213`), but the TS server awaits `Effect.runPromise` without a disconnect signal (`src/transport/gateway-projection-http.ts:84–96,131–146`). Deadline checks surround, rather than interrupt, the transform (`src/application/responses-projection-service.ts:62,87–96,112`). A disconnected client can therefore leave retrieval running until its own completion or internal limits; duration and resource cost are unmeasured. Tie the request/response lifecycle and deadline to Effect interruption, retaining worker-level cleanup. Test with a slow interruptible local transform, disconnect after it starts, and assert its finalizer runs before its nominal completion.

**G6 · P2 · CONFIRMED — The connector verifies the same prepared body twice.** `responses.go:116–139,221–238` decodes Base64, hashes bytes and compares parsed JSON, discards the resulting bytes, then `plugin/main.go:236–244` calls the same function again. This is additional allocation/CPU even for a request G1 will block. Return the already verified bytes from the client together with needed metadata; delete the second validation, not the invariant. Test that malformed or mismatched decisions still fail and benchmark allocations/time on small and near-limit bodies. No measured latency regression or monetary figure is asserted.

## Separate C03 candidate: do not credit this to main

**G7 · P2 · CONFIRMED scope limit; physical enforcement UNKNOWN.** Local comparison ref `origin/codex/013-gateway-g11-c03` at `8358c268b4c07fef2caae9d7dc1c74d34ad3ab5b` (not a live PR-status check). On *that* SHA, `integrations/bifrost/ace-connector/plugin/main.go:276–320,400–416` installs a request-bound synchronous physical-send callback and checks route and digest; the callback sends the final body to TS for an additional local authorization. `src/application/gateway-attempt-authorization-service.ts:66–83,89–114,116–148` verifies a signed receipt, claims an attempt ID in a capped process-local map, checks destination, final body and policy, and explicitly rejects stream mode. A second service instance has a different map; capacity exhaustion and a repeated ID share a denial. An accepted authorization followed by a failed or unanswered write is not proof of delivery. No replay or fault injection against a real target was performed.

Compare the multi-process design against the simpler case: one trusted connector, immutable request-local projection binding, synchronous check of the **actual** destination and serialized bytes immediately before every write; no portable allow token. Retain centralized policy where necessary, with explicit policy freshness and audit failure semantics. Keep a signed cross-process receipt or durable replay state only if the trust model requires independently transferable authority; neither makes a remote write atomic. Before adopting or deleting state, test pinned transport coverage, policy changes, restarts, two instances, capacity, sequential attempts and cancellation using a fake writer. Check ambiguity is recorded, never retried blindly. Source inspection of the callback is not observation of every upstream socket path.

## Decision fit

- ADR-014 (`docs/docs/references/ADR-014-hybrid-context-engine.md:1–8,20–38`) supports agent-neutral retrieval, not compulsory code lookup on every turn. ADR-017 (`ADR-017-bifrost-unified-llm-gateway.md:3–8,16–29`) selects one delivery owner, not a proven release. Its similarly named protocol proposal explicitly says it is superseded (`ADR-017-ace-bifrost-gateway-protocol.md:1–8`). Do not revive a second agent bridge to work around G1.
- ADR-019 (`ADR-019-functional-ddd-typespec-contracts.md:20–42`) justifies generated envelopes and typed policy. It cannot enforce matching query semantics across languages (G4). ADR-020 (`ADR-020-native-responses-only.md:8–30`) correctly separates native preparation from dispatch. Preserve native reasoning, tool/result order, multimodal content, workspace isolation, route choice and fail-closed data policy. The admission checks are not provider behavior. ADR-018 (`ADR-018-ace-context-economics-audit.md:5–19,32–46`) is historical economics evidence, not a baseline for this SHA.
- OpenSpec `013-gateway-g11-production-acceptance/specs/` separates final wire, attempt reauthorization, streaming, and real-agent economics. Follow that evidence order, not the assumption that passing an earlier layer proves the rest.
