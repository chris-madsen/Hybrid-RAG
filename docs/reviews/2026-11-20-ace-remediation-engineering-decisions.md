# ACE remediation engineering decisions — industry mechanisms, migration boundaries and adversarial acceptance

**20 November 2026 · Proposed technical supplement to the independent audit in PR #290.**

This is a **decision-quality implementation guide, not an implemented fix, approved ADR, or test report**. It refines the source findings in [the Astra static review](2026-11-19-astra-static-code-review.md) (F1–F13), [delivery review](2026-11-19-astra-delivery.md) (G1–G7), [retrieval review](2026-11-19-astra-retrieval.md), and [memory/economics review](2026-11-19-astra-lifecycle-evaluation.md). Reference tree: `main@bd170d197dcafc5cd30d0b8d6220ba6eca4fde5b`. **PR #291** is a separate, unmerged repair candidate and **PR #288** a separate, unmerged physical-send candidate. Recheck their status and diffs at implementation time; neither is silently credited to `main`.

The baseline review establishes source-path risks, not deployed incident frequency. This supplement makes the **proposed engineering choices** explicit and identifies what still needs a source check, upstream confirmation, measured comparison, or owner G02 decision. It does not require more agents, a new permanent service, a mandatory ACE token ceiling, manual approval for each model invocation, or GitHub branch-protection changes.

## Decision rules, not an extra process

1. **State the invariant before choosing machinery.** The desired property is, for example, "an older publication cannot replace a newer verified snapshot" — not "use aliases". Prefer existing native primitives when they *enforce that property*, rather than merely resemble it.
2. **One owner per side effect.** Bifröst owns physical provider writes, the workspace publisher owns index publication, the archive owns original bytes/deletion, and the measured trial collector owns usage/outcome correlation. Cross-process locks are not implied by a JavaScript queue.
3. **Build-versus-buy is a deletion exercise.** Name the existing component to retire and any compatibility or migration contract to preserve. Adding a new library while leaving two parallel production implementations is not a simplification.
4. **Keep evidence grades honest.** `SOURCE-VERIFIED` means a call path was read; `REPRODUCED` requires a failing test on the unmodified affected tree; `FIX-VERIFIED` requires that test to pass on the changed tree; `AGENT-E2E` requires observed final provider wire and completed agent work. A green CI on a separate PR does not upgrade source evidence automatically.
5. **Apply the smallest independently useful fix.** T0/T1 defects can use targeted changes plus regression tests. G02 is for materially different architecture or provider/persistence trust boundaries, not for every repair, retry, or model turn.

## R01 / F1 — publication correctness: select one writer model

**Verified failure mode:** the changed-path path upserts under `indexKey` then invokes `deletePaths` with only `workspace_id`, `repo_path`, and `exceptIndexKey`. Its per-instance `WorkspaceSync` queue is not a distributed generation fence. A stale writer can delete a newer path version.

**Option A — preferred for local, single-host ACE if supported by the actual deployment:** enforce an authoritative **single active writer for each workspace** across the complete observe → build → publish → verify → advance-manifest sequence, not merely for the delete operation. Make a second process unable to publish; it may explicitly become read-only if that mode is supported. Specify the lock's scope and filesystem guarantees, recovery after crash, and behavior if exclusivity is lost. A process-local mutex or lock per request is insufficient. A local OS-held advisory lock can be appropriate where a supported OS/filesystem supplies its semantics; a mkdir lock alone needs a deliberate stale-lock recovery policy, not silent stealing. If multiple machines or unreliable network filesystems share a workspace, **do not claim local lock correctness**.

**Option B — only if concurrent writers or zero-downtime snapshots are a real requirement:** publish a **complete, immutable, generation-identified** Qdrant collection (or a validated equivalent partition strategy), verify membership/source snapshot identity, then atomically switch the official Qdrant alias. **Critical correction to the original recommendation:** Qdrant documents **atomic alias operations**, *not* a generation compare-and-swap precondition. A delayed A can still switch an alias back to v1 after B promoted v2. Thus all promotions must be serialized/fenced by an authoritative coordinator (or a genuine tested conditional update primitive), with a monotonic, workspace-scoped generation owner. Merely reading the alias before swap is a TOCTOU check, not a fence. Avoid an unbounded number of per-workspace collections in a shared multi-tenant deployment; measure cardinality and cleanup cost before adopting B.

**Reuse:** the existing official `@qdrant/js-client-rest` and Qdrant alias operations; do not implement a parallel search server or pretend aliases solve stale-writer ordering. Source: [Qdrant collection aliases](https://qdrant.tech/documentation/manage-data/collections/) and [native alias update API](https://api.qdrant.tech/api-reference/aliases/update-aliases).

**Proof to require:** orchestrate two OS processes with barriers: A observes v1 and pauses, B observes/publishes v2 and acknowledges it, A resumes; v1 must **never** become active or delete v2. Repeat with same-generation competing content, process restart, interrupted upsert, index deletion, and a failed verification. Readers must resolve one complete snapshot; on uncertainty, signal `NOT_READY` rather than a silently incomplete successful empty search. Also test that snapshot migration/GC does not delete the active generation. Do not assert multi-process safety from green single-process unit tests.

## R02 / F2 + G2 — observed files versus verified-empty retrieval

**Minimum invariant:** `complete` and `VERIFIED_NO_CONTEXT_NEEDED` mean the relevant source snapshot is trustworthy, not merely that the existing index returned zero candidates.

For a non-Git workspace, `size + mtime` comparison is only a cheap **invalidation hint**. A same-size edit with restored mtime is not observed. In the bounded first fix, either (1) perform exact digest reconciliation before a non-Git source set can be labeled current/complete, or (2) represent observation as freshness unknown/partial and **fail closed on an empty result** until reconciliation. A watcher can reduce work but cannot be the sole proof: dropped events, process restart, overflow, or timestamp anomalies require an exact rescan or explicitly incomplete result. The cost of digest scanning large roots must be benchmarked; exact reread of a selected stale hit alone cannot recover an entirely missing candidate.

**Do not undo the valid G2 improvement in #291**: a genuinely complete, authorized, successful empty search may pass through unchanged; an *unverified* empty search must not. Compare Git and non-Git roots explicitly, with source plans and active publisher generation in test fixtures.

**Proof:** same-length content replacement + restored mtime, watcher overflow, index empty after a missed change, file deletion/rename during observation, and two successive consistent exact snapshots. Assert no `PREPARED / VERIFIED_NO_CONTEXT_NEEDED` while freshness is unknown; after proven reconciliation allow byte-identical unchanged Native Responses input.

## R03 / F3/F4/M1 — choose a recoverable memory state machine, not more ad hoc markers

**Safety invariant:** an original may be deleted without a live graph check only with positive, durable evidence that *no graph projection could have started*. Unknown, in-flight, projected, and old/ambiguous states remain fail-closed. A created:false idempotent import must not silently lose the proof forever.

**File-backed minimal candidate (before choosing a database):**
- Write a uniquely named temporary blob in the destination filesystem; flush file bytes as required by the durability contract; validate digest/size; publish without overwriting an existing immutable digest. **Do not assume `rename` implies "create if absent":** use an appropriate exclusive/link-or-verify protocol and test the target platform. Flush the containing directory where supported/required, and publish episode metadata only after its content exists and verifies. On existing digest, **read and verify**, not just swallow `EEXIST`.
- Make admission/projection state a durable, idempotently recoverable record: `ARCHIVE_PENDING` → `ARCHIVED_NEVER_PROJECTED` → `PROJECTION_INTENT_DURABLE` → `PROJECTED_OR_UNKNOWN` as applicable. The **intent must be committed before** an external graph attempt. An interruption between original and evidence publication must recover by a persisted pending transaction state, never by guessing from absent receipts. One file rename cannot atomically commit two independent final files.
- Use explicit transaction IDs and recovery rules for partial temp/metadata/proof writes; quarantine unverifiable legacy states. Serialize every graph-intent transition against deletion across processes, recheck state under the same authority, preserve tombstone-before-purge and shared-content references. Model what happens if a process dies **after a graph call** but before recording its response: graph state is unknown; do not treat a timeout as absence.

**SQLite metadata/outbox candidate — evaluate, do not mandate:** If the above requires an expanding custom write-ahead log, consider one local SQLite database for episode metadata, state transitions, projection intents/receipts, tombstones and shared-blob references. Use a real transaction (e.g. one `BEGIN IMMEDIATE` admission transition where appropriate), SQLite's cross-process single-writer serialization and bounded busy handling. For power-loss durability compare WAL + `synchronous=FULL` with the deployment's actual filesystem; WAL `NORMAL` has weaker power-loss guarantees. Keep larger originals as immutable content-addressed files if appropriate: **a SQLite transaction cannot atomically commit unrelated filesystem blob writes**. Stage/verify blob first, commit metadata last, recover unreferenced blob orphans. Do not place WAL on an unsupported network filesystem. Account for existing archive/backup format, migration, restore, locking, and shared-blob deletion before choosing it.

**Decision criterion:** compare the **smallest viable file protocol** versus **SQLite metadata transaction** on code removed, crash states, deletion correctness, backup/restore, OS support, and operational footprint. If changing persistence mechanism materially, request a bounded G02 decision; do not create a new database service. Official reference: [SQLite transactional guarantees](https://www.sqlite.org/transactional.html), [WAL](https://www.sqlite.org/wal.html), and [synchronous settings](https://www.sqlite.org/pragma.html#pragma_synchronous).

**Proof:** deterministic failpoints at every transition (partial blob, existing digest, metadata publication, archive-only proof, graph-intent before network, graph response before durable receipt, tombstone, reference decrement). Kill/restart **fresh OS processes**, retry import/reconcile/delete, verify exactly one reachable original or a typed unrecoverable/quarantined state. Two episodes sharing one blob must survive deletion of one. Old records without positive never-projected evidence must remain undeletable without verified graph absence. In particular, #291's new `markArchiveOnly` following first archive creation must be tested at the **created:true → crash → created:false** boundary; green CLI happy-path tests do not close F4.

## R04 / F5/F13 — source-plan authorization and verified provenance

**Preferred minimal repair:** pass the explicit caller source plan to the retrieval owner, and gate both computation and delivery of RepoMap/structural/LSP/other optional sources against **requested and allowed** source classes. `includeCode=true` is not an implicit permission to include arbitrary structural text. For code-only requests, an active RepoMap must contribute **zero** model-bound structural bytes. For optional requested-but-unverified sources, omit their content and retain typed diagnostic status; for required sources, return partial/blocked until provenance is verified. Do not wash away `mergeEvidence` freshness flags by overwriting `complete` using only required coverage, and do not rely on warnings subsequently dropped by the projection layer.

**If RepoMap is valuable:** make every delivered derived statement traceable to source paths/digests/ranges (or clearly label it non-authoritative outside the model-bound verified context), re-read the sources before `ready`, and reject stale aggregate maps. Retain Aider provenance/algorithm attribution; rank parity applies only when tag inputs match. Qdrant top-K followed by RepoMap reordering cannot recover a file never shortlisted; evaluate Qdrant-native grouping/overfetch and source diversity on measured multi-file tasks **before** inventing a graph search engine. Keep the canonical `ast-grep` CLI until corpus parity demonstrates that an alternate extractor is fit.

**Proof:** code-only with stale active RepoMap, requested optional map with unverifiable path, required structural map, changed file after map construction, and multi-file query whose needed path falls outside old top-K. The first must deliver no map text; the second must not turn `ready` authoritative; the third must block/partial; the last must measure accepted-task improvement as well as rank recall.

## R05 / F6/F11 — eliminate accidental full-source retention before building a GC system

The active Native Responses Gateway has no approved model-invoked `ace_expand` path. First trace every actual `ArtifactStore.readRange` consumer and response field. **If no active reader uses an artifact handle, avoid `storeExact` on that route entirely** and keep exact source reads/digests for inline verified evidence. A path to bytes in the user's workspace is not a license to persist another copy indefinitely. Preserve separate archive-original retention guarantees; this finding is about retrieval artifacts, not memory originals.

If real exact expansion remains necessary, prefer one **content-addressed** blob per verified digest with scoped, opaque handle metadata (workspace/session/expiry), a finite retention policy, safe startup recovery, and ref-aware garbage collection. Dedup by digest is not itself authorization: cross-workspace handles must not grant reads. Never delete a shared blob while a valid handle references it; never infer session expiry from an unreliable local process clock without a documented policy. Do not introduce another DB just to delete files unless persistence requirements justify it.

**Proof:** N identical retrievals do not grow stored whole-file bytes linearly; deleted workspaces do not leave indefinite accessible source replicas; expired handles fail closed; active/shared handles survive GC and restart; access from a different workspace is denied. If the store is no longer used, removal is preferable to improving an unused retention system. Separately remove obsolete tool handlers and `ace_expand` wording only after checking reachability and historical consumers.

## R06 / F7/F8/F10 — ranking, stage truth and provider provenance

- **F7 ranking:** multiplying possibly negative cosine score by `1 + boost` can *demote* a preferred file. Fix the mathematical property (higher working-context prior never lowers relative preference), e.g. a bounded additive prior on a **documented normalized score domain**, or provider-native grouping/fusion. Do not assume all configured search scores are positive or identically calibrated. Overfetch must be measured for recall, time, and real acceptance, not enabled by intuition.
- **F8 measurement:** distinguish `retrieved`, `shortlisted`, `verified`, `delivered`, `rejected_stale` and `changed_during_request`. The current `delivered` event is emitted before source rereads; do not treat that event as delivered recall. Capture true selected and final-reread-verified IDs after the last race check; include omissions from budget/dedup. Keep immutable trace IDs across stages.
- **F10 identities:** pass actual resolved provider identity/version (including active language server and embedding model) to the transform/receipt. Distinguish configured, successfully started, and probed-healthy identities; omit uncertain fields rather than supply defaults. Tie provenance to the exact provider instance used in the request, not an environment variable alone.
- **F9 hash boundary:** remove handwritten SHA-256 unless a constrained runtime demonstrably needs pure portable hashing, then use a tested maintained implementation. An adapter-level `node:crypto` digest is sufficient in Node. **If bundle IDs or receipts change**, version identifiers and test backward handling of old receipts; deterministic identity is a compatibility contract, not only a unit test. Four FNV-1a outputs do not provide SHA-256 collision resistance.

**Proof:** negative/zero/positive score ordering, feature ablations, stale-hit and post-read-race telemetry, Rust/Go/custom LSP identity, hash boundary vectors and historical receipt compatibility. No arbitrary token cap or parallel scoring pipeline.

## R07 / F12/B1/G3/E1 — measure the real product, not one convenient token column

**Existing bounded repair:** #291 changes B1's verdict toward **input+output tokens per accepted task**. That is necessary but insufficient: F12 finds that side-artifact files are only hashed and the Harbor adapter does not independently join all final egress events to accepted tasks. Successful projection is not a successful provider write.

**Trial contract (freeze before looking at outcomes):**
- Identical pinned Hermes build, tool permissions, model/provider/reasoning, workspace snapshot, task bytes, evaluator, stop conditions, and compaction policy; alternate baseline and ACE order and use fresh sessions. Include multi-file retrieval tasks and at least one no-code continuation.
- Correlate every attempted physical send to task/arm/session, prepared receipt, provider/model, exact final body digest, response usage event, retry, cancellation and terminal outcome. Hash sensitive source content; do not upload raw private transcripts merely to make a report. Missing usage, ambiguous writes or unknown outcomes are **unknown**, never zeros. The independent evaluator determines acceptance.
- For each arm, sum **all non-overlapping input+output token counts across attempts**, including failed and retried attempts; divide by the number of **accepted tasks**. If accepted count is zero the ratio is undefined. Cached-input tokens already included in input are a *subset* and must not be added twice. Report billed provider cost separately from raw token economy, plus indexing/embedding overhead and cold/warm p50/p95 latency.
- Product ratio: `(baseline total tokens / baseline accepted tasks) / (ACE total tokens / ACE accepted tasks)`, with matched quality/non-inferiority, per-family breakdown and paired uncertainty. No ≥5× release assertion from a single counterexample, fixture, input-only ratio, caller-provided `qualityNonInferior` boolean or uncorrelated trace hash. A failed task still incurs token usage and must not disappear from the numerator.
- Run the existing Harbor harness if fit; do not create a second evaluation product. Keep the historical unfavorable Codex result as negative context, not as current Hermes outcome. Structural SDLC checks cannot certify agent skill use, historical migration, or task performance.

**Proof:** missing/doubled provider usage, cached-token double-count, retry, success-without-receipt, receipt-without-send, wrong model/arm/task, multiple attempts for one task, zero accepted tasks, and the original "1000+100 versus 200+1100" false 5× example. A real task trace must show both final wire and acceptance before it is called E2E.

## R08 / G1/G4/G5/G6/G7/R5 — one actual Bifröst physical-send boundary

**Retain** the existing main's refusal until the **specific pinned Bifröst** writer and selected protocol modes pass a fake final receiver and then an authorized real provider/Hermes trial. Review the fork/upstream dependency, CodeQL findings and ABI/plugin ordering before merging #288. Do not install a second ACE proxy, direct-provider shortcut, Chat translation, or per-attempt interactive owner approval.

- **Every physical attempt:** bind actual serialized bytes, method, route, destination, provider/model and policy at **write time**, including transport retries. Check authorization immediately before the exact writer emits bytes; a pre-hook decision alone is not proof. Denied attempts must produce zero outbound writes. Keep typed `BLOCK` distinct from transport outage (`G4`).
- **Replay/restart:** signed receipts are useful only if a separate trust boundary needs transferable proof; they do not create exactly-once external side effects. A process-local consumed-ID map cannot prove global single use across independent service replicas. Either keep the writer/request-scoped authority non-transferable with one actual owner or justify a real shared replay/fence mechanism; treat ambiguous network outcomes explicitly.
- **Streaming/cancellation:** if Hermes requires streaming, reject streaming until certified. Test delta order, tool/reasoning preservation, incomplete/error terminal states, cancellations before/after first byte, and no invisible replay of partially emitted streams. Effect HTTP cancellation (`G5`) is valuable but does **not** prove the serial Python embedding worker stops computing (`R5`). Add a worker ownership/backpressure test; avoid a new queue daemon without measured need.
- **Cross-language:** reuse the one validated Go prepared byte buffer (`G6`), not a second copy in the same process. Use golden Go/TS cases for whitespace tool output, multimodal input, denied decisions, deadlines, and byte-identical no-addition request. Keep TypeSpec canonical while checking behavior in both languages.

**Proof:** fake writer counts exact writes for ALLOW, BLOCK, unauthorized provider, redirect, mutated serialized body, timeout, retry, stream disconnect and restart. Pinned fork code review must cover *all* reachable upstream write paths, not only the callback. A successful loopback receiver is still not paid-provider production certification.

## Engineering references and limits

**Primary vendor mechanisms, not evidence of ACE correctness:**
- [Qdrant collections / alias switch](https://qdrant.tech/documentation/manage-data/collections/) and [Qdrant update aliases](https://api.qdrant.tech/api-reference/aliases/update-aliases): atomic switch, **not** a guaranteed CAS/monotonic-version guard.
- [SQLite Is Transactional](https://www.sqlite.org/transactional.html), [SQLite WAL](https://www.sqlite.org/wal.html), [SQLite transactions](https://www.sqlite.org/lang_transaction.html), [`PRAGMA synchronous`](https://www.sqlite.org/pragma.html#pragma_synchronous): durability and cross-process writer behavior require the actual configuration/storage and do **not** include external files or graph calls in a single transaction.
- [Node.js filesystem API](https://nodejs.org/api/fs.html): APIs for open/write/sync/rename. Filesystem rename/flush details and crash behavior are OS and filesystem dependent; verify the deployment rather than assume portable atomic multi-file transactions.

**Still unknown:** actual deployment topology, crash consistency on target volumes, real non-Git usage, whether a true expansion consumer requires artifacts, Qdrant collection counts for the proposed alternative, exact forked Bifröst final-wire coverage, Graphiti production semantics, Hermes task quality/latency and ≥5× savings. The original audit's source lines and negative tests remain the evidence register; this proposal should not be counted as another independent reproduction.
