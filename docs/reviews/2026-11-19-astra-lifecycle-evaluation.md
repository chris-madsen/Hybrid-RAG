## Memory: the archive works; its operator-facing delete does not

The archive stores original bytes, not just derived graph facts. The Codex history adapter imports episodes; `src/application/memory-import.ts:62–148` persists originals, applies admission, creates an outbox intent for eligible episodes and separately reports projection failure. `src/domain/memory-admission.ts:23–48` is a lexical admission rule plus explicit hints and a size guard. Keywords can nominate a statement for extraction, **not** establish that the speaker made an approved decision. It is not an LLM call and not a token cap on the agent conversation. Do not enroll a second inference service until derived memory has demonstrated marginal value on tasks that require it.

`src/adapters/file-memory-archive.ts:25–50,73–87,102–111,128–165` uses a cross-process mutex, tombstones and digest checks. `file-projection-outbox.ts:164–170` fences deletion. `src/application/retained-memory.ts:41–81` orders purge → verify absence → delete original → finalize fence: an acknowledgement or timeout is not an absence proof. Keep that distinction. `memory-reconcile.ts:19–40` reconstructs projection intents; `src/bin/ace-memory.ts:110–137` asks for a real graph before processing them. No running graph consumer is supplied by the presence of a manifest or a local FalkorDB volume.

**M1 · P1 · CONFIRMED — No public delete even for an archive-only episode.** `src/bin/ace-memory.ts:37–49,85–100,206–225`: CLI can persist an ordinary transcript with no derived projection; `delete` nevertheless always constructs a Graphiti port that unconditionally throws. This is different from the runtime startup flag finding P1-MEM. A fixture operator using the supported commands saw import exit 0 (`persisted:true`, `archive_only`) and delete exit 1 (`NOT_READY`); reconcile on this archive also exited 1. The adapter-level multiprocess deletion test does **not** contradict the CLI result; it uses a different entry point. Impact: an operator cannot complete deletion using the documented tool, not evidence that private data left the machine. Minimal fix: distinguish *durably known never projected* from unknown, in-flight or previously projected. Only the first may use the existing fenced local tombstone path without graph verification. For every other state preserve the original until derived absence is verified; fail explicitly if the graph is unavailable. Do not infer ‘never’ solely from current config or a missing receipt. Regress on the actual CLI, with two episodes sharing bytes, and previously projected/unavailable and concurrent intent cases. No new database, no dependency on gateway work.

## Economics: the available fivefold comparator measures the wrong quantity

**B1 · P1 · CONFIRMED — the four-arm gate decides `fiveXAllowed` from input tokens alone.** `scripts/harbor-four-arm-gate.ts:78–119,125–145` reads and reconciles trials, then divides `hybrid-delta.rawInputTokens` by `native.rawInputTokens`; `src/domain/harbor-four-arm.ts:303–318` accepts ratios ≤0.2 when the independent predicates are true. `src/domain/harbor-four-arm-evidence.ts:215–229,279–313` already collects output and rejects repeated request IDs and paired quality losses. The arithmetic isn't blocked on a missing library or on collection of an output column.

Counterexample, **executed pure verdict + arithmetic, not a fabricated Harbor run**: one accepted task per arm, baseline input/output 1,000/100; candidate 200/1,100. Supply `assessHarborFourArmFiveX({qualityNonInferior:true,costTelemetryComplete:true,rawTrialEvidenceVerified:true,tokenRatio:200/1000})` → `allowed:true`. Total 1,100 vs 1,300, i.e. **more** tokens, not fivefold fewer. This old gate explicitly labels the arms Codex; there's no finding that a real release or real Hermes run passed incorrectly. The risk is borrowing its conclusion for the product metric. Keep the input-only ratio under that explicit name; for the actual product test compute all attempts' input+output / accepted tasks, separate cache billing and infrastructure costs, require comparable task quality and usable uncertainty. Never double-count cached input or reasoning tokens already contained in a total. Delete the unqualified decision based on the input-only ratio; regress on the example above, zero acceptances, changed quality, unknown usage and partial/failed trials. This accounting fix is independent of G1 and should precede spending money.

**Do not conflate the instruments:** `scripts/report-ace-token-savings.py:1–7,83–101` explicitly labels local receipt/character estimates. `src/domain/retrieval-quality-evaluation.ts:350–405,454–476` computes rank, payload and latency metrics, not task acceptance. `scripts/harbor_hermes_codex_oauth.py:152–186,193–209` preserves configured Hermes model/reasoning and rejects retired direct injection. Having an executable agent launcher does not establish that its candidate used the gateway. Today's accepted-task success, total/cached/output tokens, charged cost, extra latency and ongoing index cost remain **UNKNOWN**. No new extraction or inference overhead should be made mandatory to prove its own utility.

**Minimal decision experiment:** first fix the local evidence runner (R1) and metric (B1); enable only one reviewed physical route after G1; preserve identical Hermes compaction/model/effort across arms. Freeze a small retrieval-demanding multi-file task and a no-code continuation control, their independent verifier and task/image/source digests. Use unmodified Hermes vs Hermes through ACE, matched fresh sessions and balanced ordering. Record index cold/warm setup separately; per physical attempt retain route/usage/timing identifiers, not raw conversations. Stop on an uncorrelated request or missing usage; report task outcomes and failures anyway. Then expand to unseen task families and paired repeats. Optional ablations (gateway only, lexical only, graph) diagnose cost; they are not substitutes for that two-arm product comparison.

## External dependency review: #288 is not a self-contained ACE change

The head was `8358c268b4c07fef2caae9d7dc1c74d34ad3ab5b`; compare the installed main Bifröst pin `fe7634a6…` and candidate `6baf302dc73a9858bb96da017a436ef2e60f82f1`. Verified **maximhq/bifrost PR #10217 was OPEN against `dev`, at that same candidate head**. #288 CI fetches `chris-madsen/bifrost` and builds against the fork. GitHub comparison reports the new candidate **915 commits ahead** of ACE's old pin, not that its guard patch alone consists of 915 commits. The guard commit itself includes staged serialization, bounded buffers, write and context propagation (`core/providers/utils/physicalsend.go:105–219`, `roundtripper.go`, `core/schemas/context.go`). This is more than a normal public plugin hook. At inspection, #288's pinned build and TS/connector checks passed; CodeQL checks were red. A red status alone does not identify an exploitable issue. Neither a green build nor an open upstream PR certifies the final byte stream.

Keep the check immediately before physical write, with explicit denial for unsupported modes. Use the smallest known writer and measure one successful, denied and cancelled synthetic request per supported transport; neither a signed receipt nor a map creates exactly-once delivery across a network failure. If a separately trusted ACE process is required, justify receipt verification there by that boundary; do not build a distributed lease service solely to claim exactly once. Restart invalidates process-local credentials; that is safe refusal, not durable replay tracking. A fork rollout entails ABI, version, plugin-order and rollback costs: test against the exact deployed dependency, preserve the unsupported-route stop on main, and do not silently upgrade from stable upstream. See G7 for stream and retry limits.
