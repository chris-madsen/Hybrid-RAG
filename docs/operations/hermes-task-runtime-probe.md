# Local Hermes task-runtime probe (G11 / #323)

This candidate replaces the permanently blocked **agent runtime** check with an executable, isolated check. It does not replace the independent provider-wire or task-outcome gates. The native projection check stays separate.

The experiment must use an immutable, locally available task image with the approved Hermes v0.22.3 source installation (commit `5b147ab036d6d19131bff8d20701b5001eab844a`) already installed by the existing Hermes/Harbor installation process. A base image that only has Node, Python and Git is not an installed agent image. Freeze the actual image digest and rebuild the ACE bundle for it. No automatic install or pull happens during preflight. The probe validates the Hermes install root using its exact, clean Git commit when source metadata is present, or the strict packaged `install-stamp.json` when the image omits Git. It also validates the launcher digest, actual imported Responses transport and SDK 2.24.0, and verifies that the credential-pool route resolves to the configured Codex endpoint (without using credentials), then observes the native request using the SDK's terminal mock transport. CLI `local` and `upstream` version labels are accepted only when the pinned commit and version are independently matched. A stamp does not independently prove source provenance, so only use a task image whose digest and build provenance are trusted separately. It requires the complete Codex base URL from PR #384. No auth store, provider token, private task source or network is mounted into the probe.

Run the normal preflight with frozen experiment/job/bundle inputs. The same lower-level probe may be run independently:

```sh
node scripts/ace-container-runtime-smoke.mjs \
  --image "$PINNED_TASK_IMAGE" --bundle "$ACE_RUNTIME_BUNDLE" \
  --bundle-sha256 "$PINNED_BUNDLE_SHA256" \
  --hermes-endpoint-sha256 "$PINNED_ENDPOINT_SHA256" --hermes-model "$BARE_CODEX_MODEL" \
  --hermes-reasoning "$PINNED_REASONING_EFFORT"
```

A successful local receipt binds the checkout, bundle, image, Hermes commit/launcher/transport, SDK version, endpoint and bare wire model hashes, plus the observed reasoning effort. The Harbor adapter digest is checked against the current source, not the retired ContextEngine bridge. It has `providerWireCertified:false`. The Docker image must be trusted; a process in an arbitrary image can forge its own stdout. This is not a signed attestation of the deployed Bifröst listener, real OAuth, post-auth projection, protected physical send or ChatGPT response. Keep `taskRuntimeProbe` blocked until independently correlated real evidence is available. Keep all outputs local.

The feedback preflight includes a `taskRuntimeProbe.stages` summary. It binds the frozen task-image set, ACE bundle, native projection result and Hermes receipts to the current source, endpoint, model and effort. An optional local-chain receipt can separately make `bifrostSourceAndPlugin` and `localNoEgressChain` ready after the preflight validates its pinned Bifröst commit, clean checkout, plugin invocation, runtime digest, loopback boundary, single request/projection/delivery, exact body bindings, native CBM result and typed denial. The receipt has a 16 KiB read limit. A missing receipt leaves both stages `not_run`; an unreadable or mismatched supplied receipt makes them `not_ready`. The provider wire and independently accepted C07 task outcome remain `not_run`; the aggregate task-runtime check stays `not_ready` while either is unverified.

When running the exact local-chain workflow step in `.github/workflows/ace-bifrost-server-build.yml`, set `ACE_G11_CHAIN_EVIDENCE_PATH` to a new absolute path outside both the ACE source checkout and the runner checkout, for example `/mnt/d/ace-external/local-acceptance/<run-id>/local-chain-evidence.json`. The runner writes only the redacted receipt with create-only semantics and rejects paths that resolve into either checkout. Supply that file to the later preflight with `--local-native-chain-evidence <path>` and keep the preflight output directory outside the repository too. Do not hand-edit or synthesize the receipt. A separate local-chain E2E result can promote only these local stages; it does not promote the overall preflight or certify C07.

## Real local chain (no provider egress)

The pinned Bifröst build workflow exercises the actual installed Hermes SDK transport over loopback HTTP, the compiled Bifröst server with its required ACE plugin, and the compiled ACE Core with native CBM. The same Git-backed retrieval fixture is used. A synthetic, deliberately invalid bearer is only a routing fixture inside the isolated namespace. The destination allowlist is empty. A successful check requires the physical-send denial from ACE, a matching real projection receipt digest in the Core's terminal retrieval trace and policy audit, and native delivered evidence. The SDK ingress digest must equal the actual Core projection input digest, the complete trace and successful pinned CBM search must belong to the same retrieval request, the physical-attempt digest must equal the prepared-body digest for this native fixture, and the delivered fixture definition must match the current source digest. The local observation includes separate digests of the terminal trace receipt and physical-policy audit. No direct Core projection or fabricated receipt is used for this scenario. It is local integration, not a real Hermes agent loop, task-image deployment, signed provider acknowledgement, or C05/C07 certification. Keep the external task-runtime gate blocked.
