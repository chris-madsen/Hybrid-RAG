# ACE TypeSpec generation — internal context RPC v3

**Current delivery authority:** provider-native Responses only. `typespec/context-v3.tsp` is the source of the internal context RPC wire contract; its pinned OpenAPI/JSON Schema/SDK/server-type artifacts are generated by the isolated codegen package. Generation proves contract artifacts only, not provider dispatch. ADR-020, ADR-021 and OpenSpec change 013 define the current contract and acceptance gates.

## Prerequisites and local commands

Use Node 22 and npm with the repository checked out. TypeSpec's toolchain is intentionally isolated from the runtime package; `typespec/context-v3.tsp` is the internal context RPC source. Retired optional-tool/Hermes transport schemas are not part of the runnable codegen path. Run from the **repository root**:

```sh
npm ci --ignore-scripts
npm ci --prefix typespec --ignore-scripts
npm --prefix typespec run generate
npm --prefix typespec run check:sdk
npm --prefix typespec run check:native-responses
npm --prefix typespec run check:context-v3
npm run check:public-contract-types
./node_modules/.bin/tsx --test test/context-rpc-http.contracts.test.ts test/responses-projection.contracts.test.ts test/responses-projection-service.contracts.test.ts test/context-rpc-schema.contracts.test.ts test/data-class-policy.contracts.test.ts test/bifrost-plugin.contracts.test.ts
git diff --exit-code -- typespec/package-lock.json typespec/generated src/generated/ace-context
```

Only commit generated artifacts after a real supported compiler/emitter run. **Do not manually edit generated code.** Generated source families:
- `typespec/generated/openapi.json` and `typespec/generated/schema/*.json`: official TypeSpec emitters;
- `typespec/generated/sdk/**`: pinned maintained OpenAPI-to-TypeScript generator;
- `src/generated/ace-context/v3/types.gen.ts`: byte-for-byte copy of generated SDK types consumed by the real Gateway HTTP boundary.

The generator cleans `typespec/generated` before compiling, so removed models cannot leave old definitions behind. The TypeSpec GitHub Actions workflow deliberately seeds an obsolete artifact, checks its removal, mutates a tracked generated schema to verify Git detects drift, restores it and performs actual contract and adapter tests.

## Source ownership and migration strategy

- OpenSpec: desired behavior and acceptance.
- ADR-019: Functional DDD and TypeSpec-first source language decision.
- TypeSpec: **new/migrated** public wire contracts and generated integration shell.
- Domain ADTs/policy: source of semantics, authorization, provenance, final send and current provider capability.
- Generated metadata: documentation only, not a security enforcement replacement.

The prior projection schemas and DTOs are retired. The generated v3 contract is closed to unknown fields; missing/null, data class, enum, attestation and discriminated decision cases are validated against the current TypeSpec source.

Retired optional-tool and Hermes-native delivery contracts are historical evidence only. They are not generated, executed, or accepted as alternate runtime transports. Any future public contract migration must start from the active Gateway-only OpenSpec/TypeSpec authority and a separate versioned compatibility decision.

Go/Bifrost real final provider egress and Hermes agent end-to-end are separate evidence requirements. The internal RPC exposes health, capabilities, project and authorize-attempt. No delivery-recording endpoint is part of this contract. Codegen does not establish provider delivery or grant access to external providers.

## What to do when a TypeSpec check fails

Correct the source of the discrepancy in TypeSpec or the mechanical generated mapping. Do not weaken generated-diff detection, use unpinned `npm install` in CI, or add a fake decoder/default to make the check pass. New public fields/enums must update all explicit mappings and pass negative fixtures. Review the exact source HEAD and CI merge commit for every PR. If a provider test is not run, record **NOT-RUN** rather than treating an SDK mock as a provider proof.
