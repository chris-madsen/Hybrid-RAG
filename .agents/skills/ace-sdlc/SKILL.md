# ACE SDLC — thin local agent entrypoint

This skill **routes to canonical ACE instructions**. It does not replace root `AGENTS.md`, accepted ADR/OpenSpec, the SDLC command files, or the existing worktree lifecycle skill. Before invoking any vendored Matt Pocock skill, read [the ACE compatibility overlay](references/matt-pocock-compatibility.md); upstream skill text is subordinate to that overlay and the repository authorities. File presence proves repository discovery, not live agent behavior.

## Harness-neutral intent-first stage entry (R/S/A/P/X/I/V)

**Apply BEFORE the numbered SDLC steps and before R→X handoff.** The current coding harness (Hermes in local tests, but not a Hermes-specific plugin) must route by the latest owner's stage/action request and verified artifact state. Read [canonical universal entry/resume](../../../docs/operations/implementation-entry-resume.md). Explicit R → research; S → requirements / `ace-sdd-prepare`; A → `ace-architecture-design`; P → `ace-to-tickets`; X → `ace-phase-plan` (plus `ace-plan-refinement` only for genuinely required new/affected T2 synthesis); I → `openspec-apply-change` / one phase `implement_backend.md`; V → `openspec-verify-change`. An explicit "продолжай / resume" restores the **verified current R/S/A/P/X/I/V stage**, existing branch/PR and relevant hashes, not necessarily I.

**Never restart the whole pipeline by default.** Enter the requested stage directly when its prerequisite source/requirements/design/tasks/phase/evidence exist and are fresh. For missing/stale inputs do **scoped repair of the owning prerequisite** and return; do not redo completed unrelated stages or silently generate new OpenSpec trackers. A new harness session is not a new SDLC task. `sdlc:preflight` maps R=research, S/A=design, P/X=plan, I=implement, V=review; it is read-only diagnostic evidence, not stage approval. Planning can be PROVISIONAL with G02 pending; at I an explicit owner instruction to implement an existing canonical phase authorizes its **planned offline code/PR** without a second G02 interview. Only new unresolved material architecture decisions need fresh owner G02. Provider egress requires independent permission; plan existence alone or CI PASS never grants it.

**Special direct I route:** When asked to implement an existing canonical `tasks.md` / `phases/<ID>.md`, inspect exact source, phase hashes and code-level interfaces separately from acceptance dependencies, select the phase, run phase-check and `sdlc:preflight --stage implement` with task ID, plan and any available G02 crosswalk; then RED/GREEN, four reviews and an ordinary PR. Do not treat generic `G02=REVIEW_REQUIRED`, missing `--g02`, or unchecked predecessors as automatic stops on owner-directed offline code. Stop only an affected edit requiring a **specific new material design choice**; defer gated integration, egress and acceptance. Never restart R/S/A/P/X. Resume I on the same open implementation PR. Static guidance does not prove actual Hermes or another harness tool invocation.

1. Read repository-root `AGENTS.md` and scoped `AGENTS.md`; current explicit owner decisions, accepted ADR/OpenSpec and current source retain their prescribed authority.
2. Read `docs/operations/ai-assisted-sdlc.md` and choose **T0/T1/T2 by risk**, not diff size. Read `docs/research/sdlc/PROMPTS-ACE.md` and the matching **complete** `source/commands/*.md` file.
3. Run the **read-only** preflight with the **selected** stage/tier (below is a Research example only; for direct implementation use `--stage implement --task-id <task-id> --plan <canonical-tasks.md>` and `--g02 <reviewed-crosswalk>` for T2, after routing by the owner's intent):

   ```bash
   npm run sdlc:preflight -- --tier T1 --stage research --json
   ```

   `READY_FOR_AGENT` means only that local preflight has no blockers; it is **not** G02, CI, provider or production acceptance. `REVIEW_REQUIRED` means classify outstanding decisions, **not automatically stop** planned offline coding; `BLOCKED` stops only the genuinely dependent action.
4. Before branch/worktree mutation use the existing `npm run worktree:preflight -- --task-id <id> --json` and `worktree:start` commands. Reuse existing task branch/PR. Never develop on `main` or discard unrelated edits.
5. **For genuinely new/missing planning artifacts only:** **Research:** fact-only runtime tracing at exact SHA, real vs fake evidence clearly separated. **Requirements:** use scoped `ace-sdd-prepare` / `to-spec` and OpenSpec. **Architecture BEFORE slicing:** read and apply **`.agents/skills/ace-architecture-design/SKILL.md`** for AS-IS reuse, Event Storming, bounded contexts, functional ADTs/FSM only when needed, pure transitions, Effect boundaries, TypeSpec public wire and Meyer DbC. **Plan:** for material T2 work, use **`.agents/skills/ace-plan-refinement/SKILL.md`** twice: PREPARE a source-identical free-form candidate after R/S (in a separate fresh context), run the normal `.agents/skills/ace-architecture-design/SKILL.md` → `.agents/skills/ace-to-tickets/SKILL.md` → `.agents/skills/ace-phase-plan/SKILL.md` candidate in a different fresh context, then SYNTHESIZE their substantive decisions after X into one canonical plan. T0 skips this; T1 uses it only if warranted or requested. Preserve ~1,000-line forecast and all G02 gates. No routine granularity questions or parallel spec trackers.
6. **At T2 implementation:** reuse the existing G02 design consistency crosswalk and record the owner's explicit phase instruction. This authorizes in-scope offline code, not new architecture decisions or live egress. A preflight or crosswalk file alone never authorizes work. Ask G02 only for a specific new unresolved material choice. Code-stage preflight uses `--task-id`, `--plan`, and `--g02` when available; absence of `--g02` is a diagnostic review signal, not a code veto.
7. **Implement:** one approved phase, smallest change, RED before GREEN where practical, then separate BUILD, ARCH, SEC and PLAN reviews. Run `npm run test:affected` while editing and the bounded `npm run verify:pr` once for handoff. Use `npm run verify:full` only for explicit nightly/manual full verification. Run relevant actual provider/agent E2E separately; mocks cannot satisfy it.
8. Use **`.agents/skills/ace-stage-handoff/SKILL.md`** for review-overlap planning: a PR per completed R/S/A/P/X stage; downstream branches/PRs **stack on the preceding stage branch**, never conflicting direct-to-main PRs. Record input artifact hashes, source branch HEAD and actual CI-tested checkout SHA separately. No automatic merge; new unresolved G02 decisions and real egress remain hard gates for their affected actions, not repeated per-phase code approvals.
9. Before context handoff fill `docs/research/sdlc/source/templates/progress-checkpoint.md` and re-read live Git/source on resume.

## Staged pipeline route

For requests to run the complete staged SDLC or prepare architecture/phase plans across reviews, read and follow **`.agents/skills/ace-stage-handoff/SKILL.md`** and **`docs/operations/staged-sdlc-pipeline.md`** in full. The normal T2 planning order is verified Research → Requirements OpenSpec → **`ace-plan-refinement` PREPARE** (private free-form A on the same R/S/source input) → independent Skills B: **`ace-architecture-design`** → `ace-to-tickets` → **`ace-phase-plan`** → **`ace-plan-refinement` SYNTHESIZE** (decision-level A/B comparison and canonical C) → G02 owner review for genuinely unresolved decisions → owner-directed Implement slice → cross-phase Verify. In-scope offline T2 code does not require repeated G02; new material decisions and egress still do. A/B runs are sequential and must use fresh isolated contexts for a genuine independence claim. Planning may progress provisionally before G02; **owner-directed in-scope offline implementation of an existing canonical T2 phase MAY proceed** without a repeated G02 signature. A new material architecture decision or provider egress is still gated. The router is an instruction workflow for the currently active agent, not a background daemon.

## To-tickets / Plan route (automatic default)

For requests to "make the implementation plan", "split into tasks/chunks" or "to-tickets", first confirm a reviewable **architecture design** exists; then follow **`.agents/skills/ace-to-tickets/SKILL.md`**. It replaces the upstream sizing interview with ~1,000-line forecasts (including tests). For material T2 planning, call **`.agents/skills/ace-plan-refinement/SKILL.md`** in PREPARE mode after shared R/S; follow the normal **`.agents/skills/ace-phase-plan/SKILL.md`** and invoke refinement again in SYNTHESIZE mode after X. Validate **every final C phase** with `check:ace-phase-plan`. Never present same-context alternatives as independent. No count is hard-coded. G02, provider permission, actual tests and owner-controlled implementation remain separate.

## SDD preparation route (explicit user request)

When the owner asks for "prepare SDD", "ace-sdlc prepare", or conversion of a task into a canonical OpenSpec spec, read and follow **.agents/skills/ace-sdd-prepare/SKILL.md** in full. It routes fact-only Research → conditional Matt grill-with-docs/domain-modeling → to-spec synthesis → openspec-propose/update-change → structural acceptance checks and G02 owner-review handoff. Do not launch implementation while preparing SDD. Do not use this route for trivial T0 work or create duplicate OpenSpec changes. The read-only check:sdd-prepare never approves G02.

Local dry-run procedure and explicit negative checks: `docs/operations/local-agent-sdlc-trial.md`.
