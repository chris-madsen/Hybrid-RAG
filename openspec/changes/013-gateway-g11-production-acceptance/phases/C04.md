## Objective

**Observable behavior:** Provider-native Hermes OAuth, exact model/effort and final-wire store:false are certified or explicitly blocked; provider-native context window/counter are observed without a guessed ACE-side token ceiling or truncation; a fallback changing provider/residency requires fresh policy evaluation, and timeouts/secrets never allow passthrough.

## Source findings at the C04 entry pin

Static inspection of the Bifröst review candidate `6baf302dc73a9858bb96da017a436ef2e60f82f1` (open PR #10217, not merged upstream) found:

- `core/schemas/physicalsend.go:15-27` exposes attempt ID, provider, model, method, destination, body and digest to the physical-send authorizer, but no credential-source or OAuth-route identity.
- `core/bifrost.go:8559,8702` sets a core-owned provider/model route for each provider attempt; `core/providers/utils/physicalsend.go:213-230` carries that actual route into the final-send authorizer. This lets C04 audit changed provider/model fallbacks without treating the original route as current.
- `core/providers/utils/utils.go:3650-3672` converts a `PhysicalSendAuthorizationError` to a Bifröst error with `AllowFallbacks=false`; `core/providers/utils/makerequest_test.go:1208-1245` asserts a denial opens zero provider connections. This is the upstream fail-closed oracle for authorization errors.
- `core/providers/openai/openai.go:88-103` returns a key with nonempty `Value` unchanged; it only mints a bearer from `OAuthKeyConfig` when the static value is empty. Thus the credential selected for an attempt cannot be inferred from the provider name or bearer header.
- `core/schemas/account.go:1422-1435` and `core/providers/utils/tokencache/oauthkey.go:61-113` define generic `client_credentials` and `jwt_bearer` OAuth grants. They do not establish Hermes/Codex subscription OAuth entitlement.
- Therefore this C04 candidate does not claim OAuth support or accept an operator-supplied route assertion. ACE returns `OAUTH_ROUTE_UNVERIFIED`; a future implementation must carry trusted route provenance from Bifröst key selection before any provider send can be enabled.

## Architecture contract

- Owning bounded context: Gateway policy/identity domain, Bifröst credential selection and native provider serializer.
- Event Storming: Hermes submits request/tool result; ACE prepares verified evidence; Bifröst proposes a network send; policy accepts or denies; provider may complete/fail/incomplete; Harbor observes task outcome. This phase owns only its indicated part, not a new event bus.
- Proposed immutable `State | Command | DomainError` contract: use read-only input/receipt/attempt ADTs and pure `decide`/`validate` functions at the domain boundary; Event only as an observed fact, no mandatory OO aggregate. FSM state transitions apply to single-use send permits, N/A for stateless projection.
- Application/ports: existing TypeScript Effect policy, audit and context-transform services; real cancellation and idempotency at the adapter boundary. No duplicated provider credential storage.
- Adapters/provider: existing thin Go Bifröst plugin and versioned authenticated ACE local HTTP; Bifröst native Responses provider route is **not yet certified**.
- Security/identity: No API-key substitution, no hidden provider conversation, no mutable raw-body bypass or secret-leaking fallback.
- Source provenance: pin exact original/projected body digests, provider/model, agent-visible session correlation (not authentication), source SHA and provider-wire evidence class.
- ADR/OpenSpec: ADR-007/009/017/019, accepted change 010 as historical behavior boundary, change 013 G11 and native Responses specs, change 002 Harbor.
- Reuse: Bifröst native schemas/streaming, existing TS/Effect Gateway and TypeSpec compiler, existing Harbor; inspect exact maintained implementations instead of building a replacement.
- Removal: remove all previous projection contracts and compatibility implementations; TypeSpec v2 is the only active contract.
- Rollback/STOP: Revoke test-only attempt eligibility, block unchecked external sends and preserve policy denial/audit. Owner already permits guarded disposable C03–C05 native Responses probes; exact provider/model/OAuth/privacy still need phase-specific G02 and transmission-time verification. Never introduce an ACE-invented token ceiling or truncation.
- Phase integration: downstream phases consume immutable verified outcomes, **never** treat `PREPARED` as a permit or replace a missing upstream gate with optimistic fixtures.
