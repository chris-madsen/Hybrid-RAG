## Objective

**Observable behavior:** A stateless native Responses request with multi-turn function call/results, reasoning, multimodal items, stream flag and opaque extensions yields exactly one additive untrusted developer evidence item, while all original items are preserved and no provider is contacted.

**Non-goals:** no new ACE proxy/agent scheduler, model-invoked context tool, alternate-protocol fallback, direct provider credential bypass, token gate or silent fake completion.

**Definition of accepted:** every owned scenario below passes its cheapest deterministic tests and its specified external evidence gate; independent G02 decision and required egress are observed, not inferred from structural tests.

## Requirements and invariants

| ID | Required ensure/postcondition | require/precondition | exceptional/negative oracle |
|---|---|---|---|
| RESP-004 — Lossless Responses multi-turn input projection | ACE inserts only clearly marked untrusted verified source evidence while preserving the full original input-item order and protected provider parameters | Hermes submits stateless Responses input with function_call, function_call_output, matching call_id, reasoning/opaque content, multimodal blocks, streaming and vendor extensions | does not translate into another message format, invent a truncated history, drop model controls or claim a real Hermes loop from synthetic replay alone. |

- **invariant:** Projection returns PREPARED rather than a send permit; source policy and payload hashes are bound before exposing any bytes.
- **frame:** all original Responses input items, function-call IDs, reasoning/opaque fields and protected data remain unchanged except the approved additive context; unrelated ACE contexts remain untouched.
- **exceptional:** every policy, provider, freshness, audit, timeout, source SHA and replay failure produces typed BLOCKED, UNKNOWN or PARTIAL as applicable, with zero unauthorized new provider sends; recovery never changes protocol.

## Architecture contract

- Owning bounded context: Gateway native domain, Effect context transformation and the thin Go connector.
- Event Storming: Hermes submits request/tool result; ACE prepares verified evidence; Bifröst proposes a network send; policy accepts or denies; provider may complete/fail/incomplete; Harbor observes task outcome. This phase owns only its indicated part, not a new event bus.
- Proposed immutable `State | Command | DomainError` contract: use read-only input/receipt/attempt ADTs and pure `decide`/`validate` functions at the domain boundary; Event only as an observed fact, no mandatory OO aggregate. FSM state transitions apply to single-use send permits, N/A for stateless projection.
- Application/ports: existing TypeScript Effect policy, audit and context-transform services; real cancellation and idempotency at the adapter boundary. No duplicated provider credential storage.
- Adapters/provider: existing thin Go Bifröst plugin and versioned authenticated ACE local HTTP; Bifröst native Responses provider route is **not yet certified**.
- Security/identity: Projection returns PREPARED rather than a send permit; source policy and payload hashes are bound before exposing any bytes.
- Source provenance: pin exact original/projected body digests, provider/model, agent-visible session correlation (not authentication), source SHA and provider-wire evidence class.
- ADR/OpenSpec: ADR-007/009/017/019, accepted change 010 as historical behavior boundary, change 013 G11 and native Responses specs, change 002 Harbor.
- Reuse: Bifröst native schemas/streaming, existing TS/Effect Gateway and TypeSpec compiler, existing Harbor; inspect exact maintained implementations instead of building a replacement.
- Removal: remove all previous projection contracts and compatibility implementations; TypeSpec v2 is the only active contract.
- Rollback/STOP: Stop projection and preserve inactive/archival v1 DTO only; no unmodified provider forwarding. G02 on native v2 input contract and source policy; unverified provider-held history remains unsupported.
- Phase integration: downstream phases consume immutable verified outcomes, **never** treat `PREPARED` as a permit or replace a missing upstream gate with optimistic fixtures.

## Task steps

1. Inspect request-binding/attestation and ContextTransformService ports; reuse only protocol-neutral validation and do not import previous contract DTOs into the v2 domain.
2. RED: native input with function_call + function_call_output + matching call_id and encrypted reasoning must survive roundtrip in test/responses-projection.contracts.test.ts; current main lacks the v2 domain module.
3. RED: reject non-native body fields, hidden previous_response_id/conversation/thread IDs, implicit store:true/omitted, model mismatch, invalid Base64 and unattested fabricated session provenance.
4. Implement immutable native input/projected payload functions; preserve every original JSON input item and tool/effort/stream/unknown key and add a clearly delimited untrusted developer evidence item.
5. Implement Effect orchestration through existing context-transform-service.ts and policy-service.ts, with secret detection and actual source revalidation, returning PREPARED/BLOCK only.
6. Implement thin Go v2 client with bounded loopback URL, auth token, no redirects, SHA-256 verification and semantic diff validation; never implement Go source-retrieval business logic.
7. Switch runtime composition to the new v2 service only after retirement tests pass; do not permit Bifröst external generation from PREPARED.
8. GREEN: verify multiline input and tool-only continuation, cancellation, mismatched IDs and no alternate-protocol fallback; rerun isolated Go tests, TS lint/types/affected suite.

9. Run four independent BUILD/ARCHITECTURE/SECURITY/PLAN COVERAGE reviews, record effective source/binary SHA and exact CI checkout; block if required approvals or live evidence are absent.
