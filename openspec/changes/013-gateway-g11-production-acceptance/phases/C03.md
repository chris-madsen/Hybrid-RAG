## Objective

**Observable behavior:** Every physically dispatched native request, including inner Bifröst retries/extraAttempts, must pass an authenticated, single-use final-send permit for its exact body/provider/model; race/replay cannot reuse a previous decision.

**Non-goals:** no new ACE proxy/agent scheduler, model-invoked context tool, alternate-protocol fallback, direct provider credential bypass, token gate or silent fake completion.

**Definition of accepted:** every owned scenario below passes its cheapest deterministic tests and its specified external evidence gate; independent G02 decision and required egress are observed, not inferred from structural tests.

## Requirements and invariants

| ID | Required ensure/postcondition | require/precondition | exceptional/negative oracle |
|---|---|---|---|
| RESP-005 — Final physical-send authority | every actual physical provider-bound send has a fresh single-use ACE decision bound to final exact bytes, provider/model/destination, source policy and audit identity | the pinned Bifröst dispatches, retries, re-routes, internally falls back or applies another mutator | an outer HTTP/PreLLM hook, a prior receipt or an unverified internal retry never grants send permission. |
| G11-009 — Second attempt after transient failure | mint or derive a distinct single-use attempt identity and perform fresh ACE authorization against the exact final model-bound body before any second send | Bifröst intends to retry the same provider/model after an initial attempt | the original ingress APPLY receipt alone SHALL NOT authorize the retry |
| G11-011 — Reused, stale, raced or mismatched receipt | deny the attempt with an auditable typed outcome, including concurrent attempts and process restart where applicable | a receipt belongs to a different physical request, attempt number, session correlation, body digest or provider/model, or is consumed twice | do not reuse a permitted decision merely because an inbound digest matches |

- **invariant:** PREPARED and outer PreLLM can never authorize invisible inner attempts. A callback immediately before `req.Write(bw)` may identify the attempt but **cannot by itself attest serialized final bytes**: writes/flush may occur inside serialization. The first physical socket byte MUST wait until that attempt's exact serialized native body and provider/model/destination policy are checked and its single-use permit atomically consumed. Unsupported transport, raw-body and one-shot streams remain blocked.
- **frame:** all original Responses input items, function-call IDs, reasoning/opaque fields and protected data remain unchanged except the approved additive context; unrelated ACE contexts remain untouched.
- **exceptional:** every policy, provider, freshness, audit, timeout, source SHA and replay failure produces typed BLOCKED, UNKNOWN or PARTIAL as applicable, with zero unauthorized new provider sends; recovery never changes protocol.

## Architecture contract

- Owning bounded context: Bifröst actual final physical dispatch and TS pure attempt policy.
- Event Storming: Hermes submits request/tool result; ACE prepares verified evidence; Bifröst proposes a network send; policy accepts or denies; provider may complete/fail/incomplete; Harbor observes task outcome. This phase owns only its indicated part, not a new event bus.
- Proposed immutable `State | Command | DomainError` contract: use read-only input/receipt/attempt ADTs and pure `decide`/`validate` functions at the domain boundary; Event only as an observed fact, no mandatory OO aggregate. FSM state transitions apply to single-use send permits, N/A for stateless projection.
- Application/ports: existing TypeScript Effect policy, audit and context-transform services; real cancellation and idempotency at the adapter boundary. No duplicated provider credential storage.
- Adapters/provider: existing thin Go Bifröst plugin and versioned authenticated ACE local HTTP; Bifröst native Responses provider route is **not yet certified**.
- Security/identity: The first PREPARED result and the outer PreLLM hook can never authorize invisible inner attempts; no verified seam means zero send.
- Source provenance: pin exact original/projected body digests, provider/model, agent-visible session correlation (not authentication), source SHA and provider-wire evidence class.
- ADR/OpenSpec: ADR-007/009/017/019, accepted change 010 as historical behavior boundary, change 013 G11 and native Responses specs, change 002 Harbor.
- Reuse: Bifröst native schemas/streaming, existing TS/Effect Gateway and TypeSpec compiler, existing Harbor; inspect exact maintained implementations instead of building a replacement.
- Removal: remove all previous projection contracts and compatibility implementations; TypeSpec v2 is the only active contract.
- Rollback/STOP: Disable unchecked network sends, retries and fallbacks; retain existing fail-closed PreLLM until the verified replacement is installed. The selected `RoundTrip` seam still needs a versioned upstream patch, serialization/byte guard and single-use consume/replay tests. Only owner-authorized disposable PUBLIC probes may send **after** C03/C04 guard and privacy checks, even while C05 ordinary route certification is pending.
- Phase integration: downstream phases consume immutable verified outcomes, **never** treat `PREPARED` as a permit or replace a missing upstream gate with optimistic fixtures.

## Task steps

1. **Observed:** inspected the pinned Bifröst retry worker, `core/providers/utils/roundtripper.go`, provider request serialization and plugin lifecycle. The pre-serialization callback was rejected as a final-byte oracle because request serialization may write before flush.
2. **Implementation candidate:** the upstream worktree adds request-scoped `PhysicalSendGuard`/core route facts, a private HTTP-transport-to-core state bridge, bounded full-request staging before provider connection acquisition, authorization of staged body/provider/model/destination, and exact staged-byte write only after ALLOW. It denies one-shot/oversized bodies and prevents unauthenticated internal-child sends. This design is proposed for G02 review; it is not owner-approved.
3. **Local negative oracles implemented:** scripted transport tests cover denial/no connection, stale-connection retry with fresh attempt IDs, one-shot/oversized bodies, changed body, missing guard on an internal child, expired guard deadline and no fallback on authorization errors. Plugin/connector tests add route, receipt and semantic mismatch cases. Provider `extraAttempts`, redirected wrappers, actual cancellation and crash/restart still need phase-specific review/evidence.
4. **Local authorization tests implemented:** duplicate/reused attempt IDs, concurrent duplicate calls (one ALLOW only), changed provider/model/destination/prepared digest, tampered/expired receipt, deadline expiry, non-Responses route, `stream:true`, process restart and audit failure all fail closed or return the typed decision. Audit details retain request/attempt IDs, provider/model/destination, both body digests and a digest of the signed projection receipt; body text, receipt tokens and credentials are not stored. The per-process registry is a bounded synchronous Map, not durable CAS/lease storage; its acceptability is G02 REVIEW_REQUIRED.
5. **Implementation candidate:** TypeSpec-generated `ALLOW|BLOCK` request/decision contracts, pure input validation, signed projection-receipt verification, policy/audit Effect service, and a bounded process-local attempt-ID registry are present. The ephemeral receipt key makes restart invalidate pending attempts. This does not satisfy a durable cross-process CAS requirement if the runtime deployment shares an endpoint across processes; that topology must remain unsupported or be reviewed before enablement.
6. **Implementation candidate:** the Go connector binds the receipt's prepared-body SHA to a separate actual-wire-body SHA. It compares the prepared and staged JSON semantics using `UseNumber`; only object-key order, insignificant whitespace and the native `stream:false`/omitted default are normalized. Number lexemes, arrays, content, tool/reasoning fields and every other value remain significant. ACE authorizes the exact actual body bytes and exact route; the Bifröst plugin performs the semantic relation check before calling the authenticated local endpoint.
7. **Local GREEN evidence:** TypeScript service/HTTP contract tests, connector HTTP tests, plugin local-loopback tests and scripted Bifröst transport/schema tests are implemented. They use only fake ACE endpoints and scripted/local sockets; they are not provider-wire evidence. A pinned plugin build and all results must be recorded at the exact committed source SHA.
8. **External gate NOT RUN:** no real provider, Hermes agent or Harbor run is made. The ACE destination/provider/data opt-ins default closed; `stream:true` remains blocked. A disposable PUBLIC probe is still eligible only after the C03 guard and C04 exact target/privacy controls are reviewed and verified.
9. **Reviews NOT RUN:** four distinct BUILD/ARCHITECTURE/SECURITY/PLAN COVERAGE evidence reviews and explicit G02 owner review remain open. One-agent self-review is not independent approval.
10. **Delivery pending:** commit and push focused ACE and upstream Bifröst PRs, verify the compatible pinned plugin build, then re-run the canonical phase checker against the updated plan/spec fingerprints. The C03 acceptance checkbox remains open until its external evidence and owner gates are observed; no unsupervised merge.
