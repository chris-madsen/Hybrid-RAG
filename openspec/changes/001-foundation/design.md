# Design — Foundation: workspace truth, safety and Gateway boundary

## Context

Trustworthy ACE evidence requires stable workspace identity, explicit policy, current source bytes and one agent-facing context-delivery owner.

## Goals

- Safe local workspace identity and verified reads.
- Explicit data-policy and authorization gates.
- TypeScript + Effect modular-monolith domain/application boundaries.
- Automatic request-local context delivery only through Bifröst Gateway Projection.
- Exact authorized source retention without silent truncation.
- Read-only behavior with respect to the user worktree.

## Boundaries

1. Domain owns workspace identity, source/evidence invariants and typed failures.
2. Application owns ports and orchestration; concrete filesystem/provider clients live in adapters.
3. Bifröst is the sole agent-facing delivery adapter and calls the versioned local Gateway Projection API.
4. Retrieval/vector/LSP/memory/provider infrastructure remains behind typed ports; no external dependency becomes a new domain owner.
5. A provider/tooling failure is explicit `not_ready`/`unavailable`/denied state, never fabricated success.

## Source preservation

ACE may return concise projected evidence, but exact verified source/generated bytes remain available internally for authorized retrieval/re-projection. A transport/body limit may cause an explicit BLOCK or partial capability; it never authorizes silent loss of required bytes.

## Security

Workspace/data-class authorization is checked before provider effects and again at actual egress where applicable. Source text is untrusted data. The Gateway never grants write authority over the user's source tree.

## Transport authority

Current transport ownership is defined by active change `010-gateway-only-ownership`. Historical model-invoked tool and native agent-specific delivery experiments are not alternate foundation boundaries.
